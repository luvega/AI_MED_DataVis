# 第1章 医药数据分析导论

## 本章定位

第 1 章是全书入口，说明本课程在药学专业培养中的位置。本章不展开代码和统计细节，而是帮助学生建立三组共同语言：药学问题如何进入数据表，数据分析如何服务药学判断，AI 工具如何辅助学习但不替代专业判断。后续章节会把这些共同语言落实到数据读取、清洗、统计、图表和组学案例中。

## 小节目录

### 1.1 医药数据处理与可视化的课程定位

- 本课程不是单纯 Python 或 R 语法课，而是围绕医药问题组织数据、方法、图表和解释。
- 本课程连接药学专业基础课、统计学、生物信息学和科研训练。
- 对药学学生而言，数据能力不是脱离专业的编程技能，而是理解药物研发、药效评价、安全性监测和精准用药问题的辅助能力。
- 课程主线包括数据读取、清洗、描述统计、统计推断、基础建模、规范可视化和 AI 核验。
- 软件工具服务分析目标，不能替代变量理解、方法选择和医学解释。
- 学习本课程时应先问“这个药学问题是什么”，再决定数据、方法和图表。
- 学生需要形成可提交的学习证据，包括数据字典、清洗记录、图表、代码、报告和 AI 协作记录。

### 1.2 医药数据的主要来源与常见形态

- 医药数据可来自药品销售、临床指标、实验记录、公共数据库、组学矩阵、单细胞对象和文本资料。
- 药学场景中的数据可来自药物分子、处方与销售、药效实验、安全性评价、临床指标、公共数据库和组学实验。
- 不同来源的数据在样本单位、变量类型、缺失机制、权限和解释边界上不同。
- 同一药学问题可能同时涉及化学结构、实验指标、临床结局和文献文本，学生需要先分清数据层级。
- 表格数据适合入门训练，组学和单细胞数据用于理解高维、小样本和参数敏感性。
- 公共数据也需要记录来源、下载时间、许可和字段含义。

### 1.3 样本、变量、结局与分组

- 样本是分析中的观察单位，可能是患者、样本、细胞、基因、药品或一次测量记录。
- 药学数据中的观察单位可能是化合物、处方、患者、样本、细胞或基因，不能默认“每一行就是一个患者”。
- 变量包括数值、分类、日期、文本、ID 和矩阵特征，变量类型决定清洗、统计和作图方式。
- 结局变量、解释变量和分组变量要在分析前写清，不能做完图后再倒推问题。
- 药效、安全性、暴露剂量、分组、批次和时间点应优先识别，因为它们会影响后续统计和解释。
- ID、批次、时间点和重复测量容易被误用，需要在数据字典中明确标注。

### 1.4 从医学问题到数据分析问题

- 一个医学或药学问题需要转化为可分析的数据问题，写清对象、变量、比较方式和期望产物。
- 学习方法上采用“问题定义 -> 数据结构 -> 方法选择 -> 图表表达 -> 结果核验”的顺序。
- 初学者不要从代码开始学，而要先写清分析对象、变量关系、预期图表和不能回答的问题。
- 不是所有问题都能由当前数据回答，不能把相关、预测或可视化模式写成因果结论。
- 分析前应区分描述、比较、关联、预测和解释机制这几类任务。
- 每次使用 AI 前，先给出自己的问题拆解；AI 输出后，再按变量、方法、结论边界逐项检查。
- AI 可以帮助拆解问题和检查表达，但不能替学生决定医学含义和证据强度。

### 1.5 学习产物与课程项目要求

- 每章学习不只看“是否听懂”，还要看能否提交可检查产物。
- 本课程的学习方法是持续产出小型证据，而不是期末一次性完成报告。
- 核心产物包括代码、运行结果、图表源数据、图表说明、清洗记录和简短解释。
- 每次作业都应留下“原始问题、数据理解、处理步骤、结果解释、AI 核验记录”。
- 综合项目需要保留数据来源、处理步骤、统计方法、图表契约和 AI 协作记录。
- 期末项目评价重点不是模型复杂度，而是问题是否清楚、数据是否可追踪、图表是否能支撑结论、AI 使用是否透明。
- 学生应在报告中说明哪些内容来自 AI 辅助，哪些经过人工核验和修改。
