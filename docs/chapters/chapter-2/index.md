# 第2章 AI 生产力工具链与项目环境

做同一份练习，文件也已经复制齐全，同学的电脑能读入表格，自己的电脑却提示找不到文件。这时可以先检查终端当前所在的目录。例如，文件保存在项目的data文件夹里，从项目根目录运行时，相对路径data指向这个文件夹；从scripts文件夹运行时，程序就会在scripts下面寻找data。相对路径从当前工作目录出发，运行位置不同，找到的位置也会不同。

本章配置前几章练习所需的工作环境，明确程序怎样启动、输入文件放在哪里、结果保存到哪里，并检查所需工具能否正常运行。

## 2.1 本地 AI 工作台的基本组成

### 按职责认识工具

本课程使用WorkBuddy作为AI工作前台。它帮助组织任务和材料，但数据分析仍要由实际的程序和文件完成。为了判断问题发生在哪里，需要区分几个层次。

| 组成 | 主要作用 | 最小检查 |
| --- | --- | --- |
| AI工作前台 | 组织任务、提供解释或协作建议 | 能进入指定项目并查看本次任务信息 |
| 编辑器 | 查看和修改文本、代码 | 能保存文件，并辨认保存位置 |
| 终端 | 向程序发送命令，查看返回信息 | 能显示当前目录和命令输出 |
| Python与R | 执行代码 | 能运行最小计算和本章验收脚本 |
| 环境管理工具 | 隔离项目依赖 | 能说明使用哪个环境和实际程序入口 |
| Git | 记录文件版本及差异 | 区分软件可用与当前仓库可用 |
| Pandoc | 转换文档格式 | 当前需要转换时，再检查入口和产物 |

终端不是另一种编程语言。你在终端中输入的命令，可以启动Python、R或其他程序；程序是否能够启动，与代码本身是否正确是两项检查。编辑器显示了某个脚本，也不意味着终端已经切换到该脚本所在的目录。

“本地工作台”只说明你在自己的电脑上组织工作，并不保证每一步都在本地完成。AI服务、扩展功能或脚本可能访问网络。涉及未公开研究、患者资料或账号凭据时，应先确认授权和数据流向，不能仅凭文件在本机就认定没有外传风险。

### 前5章需要到什么程度

第四章需要Python的pandas和基础R；第五章的配套图使用matplotlib，Excel读取使用openpyxl或R的readxl。它们按任务准备，不必提前安装后续所有统计和组学包。

本章提供[前5章最小环境包](assets/first-five-environment/README.md)。旧的[通用环境包](assets/starter-project/README.md)仍供后续使用，但不要在尚未用到相应内容时同时恢复多套环境。环境越多，越需要明确当前调用哪一套。

## 2.2 WorkBuddy 工作空间、任务对话与结果核验

### 先确定工作空间

工作空间是本次任务使用的项目目录。建议为课程练习建立独立文件夹，不把整个个人文档目录或含敏感材料的上级目录作为默认范围。先查看完整路径，再确认其中有哪些文件。

安装、账号操作和界面位置可能随产品更新。需要这些操作时，查阅[WorkBuddy官方入口](https://www.workbuddy.cn/)的当前帮助。本章关注稳定的检查动作，不要求记住某个按钮的位置。

第一次进入项目时，可以提出一个只读请求：

> 请说明当前工作空间中的目录和文件用途。不要安装软件，不要执行分析代码，不要修改、移动或删除文件，也不要读取凭据。无法确认的用途请标为待确认。

随后自己核对文件列表。比如，你打开的是本次练习文件夹，其中有data、scripts和outputs三个目录。如果AI却开始解释隔壁另一个项目的文件，即使解释听起来合理，也还没有建立本次任务的共同上下文。先对照它报告的完整路径，再确认data里确实是老师发下来的输入，而不是上次练习的同名结果。此时修正的是“正在处理哪个项目”，不需要改动分析方法。确认了这一点，才继续交代下一项任务。

### 一次任务怎样验收

在任务对话中，只提供完成当前工作所需的材料。可以引用指定文件、指出真实路径，并交代已经做过的处理；不要为了“信息充分”把无关个人资料和凭据一并加入。

执行过程中，查看拟操作的对象和范围。写文件、安装包、访问网络、覆盖结果是不同操作，不应因为其中一项合理就默认全部允许。项目规则能帮助约束协作，但权限提示仍要按具体动作判断。

结束时，不能只读AI的总结。应打开实际产物，检查文件名、内容、保存位置和变更范围；若涉及代码，还要核对实际运行信息。任务界面显示完成，只说明工作流程到达某个状态，不证明科学解释正确。

例如，AI声称“已生成环境报告”，你应能找到对应文件，里面应有实际程序入口、版本和检查结果。若只有一句“环境正常”，还不足以说明第四章的代码能够运行。

## 2.3 Git、Node.js、Miniconda 与 Pandoc

### 先让 Python 和 R 跑起来

Python环境不仅包括解释器，还包括当前安装的扩展包。电脑上有多个Python时，终端可能调用了与预期不同的程序。以下命令只报告当前入口和版本，不安装软件：

```powershell
python -c "import sys; print(sys.executable); print(sys.version)"
Rscript --version
```

若提示命令不存在，先确认软件是否安装，以及入口能否被终端找到。使用完整程序路径也可以检查，但不应把自己的个人路径写进供全班使用的脚本。Windows PowerShell中，带空格的程序路径需要用引号括起，并用调用运算符启动；具体路径以本机为准。

把最小环境包复制到独立学生项目后，在该包目录执行：

```powershell
python check_python.py
Rscript check_r.R
```

Python脚本报告解释器、版本、工作目录和三个所需包；缺包时返回非零退出状态。R脚本检查基础运行，并单独报告Excel练习所需的readxl是否可用。readxl未配置，不阻止基础CSV练习，但不能把Excel练习记为已经通过。

这些输出应保存到环境检查记录中。运行命令、当前路径、真实输出和退出状态放在一起，才便于他人复查；不要根据教材或同伴电脑填写版本号。

### Miniconda 管理的是环境，不是分析结论

Miniconda可以为不同项目建立独立的Python环境。课程包中的`environment.yml`描述环境名和依赖，不等于已经在你的电脑上安装成功。准备创建环境前，应确认这是当前任务需要的配置，并由教师或维护者核对来源和兼容性。

如果选择本章的最小配置，可在确认安装范围后执行下面的配置命令；它会下载并安装依赖，不属于只读检查：

```powershell
conda env create --file environment.yml
conda run -n medical-data-first-five python check_python.py
```

若已有同名环境，不要直接覆盖或删除。先查清它属于哪个项目，再决定复用还是建立另一环境。也不要为了保存本机配置而覆盖课程发放的原始文件；另存记录，例如`records/environment-local.yml`，并说明生成方式。

R独立于Python环境运行。前5章的核心任务使用基础R；后续需要更多包时，再按对应章节恢复项目环境。不要因为后面会学习RNA-seq，就在第一次验收中把整套相关依赖列为必需项。

### 其他工具按任务进入

Git负责版本记录。`git --version`能返回版本，只说明软件入口可用；`git status`还要求当前目录属于有效仓库。即使文件夹中有一个名为`.git`的目录，也不能据此认定历史可恢复。建立了仓库，也仍需要实际提交，才能保存相应版本。

Node.js是JavaScript运行环境，npm是常见的包管理入口。只有当前工具或任务明确依赖它们时，才把它们纳入验收；本章Python/R练习不因此增加额外安装要求。

Pandoc用于文档格式转换。能够执行`pandoc --version`不等于已经生成了合格报告。真正使用时，还需要打开转换产物，检查中文、公式、图片和链接。

工具的状态可以分别记为“通过”“待配置”“不适用”或“需人工确认”。暂时不用的工具标为不适用，比未经检查就写通过更准确。

## 2.4 Skills 的安装、调用与课程使用边界

Skill通常包含面向某类任务的说明，以及可选脚本、模板等资源。它可以帮助重复执行有明确规则的工作，但并不是安装后就自动可靠的功能包。

使用前先看来源和内容：它准备读什么、写什么，是否调用外部服务，是否安装依赖，以及发生问题时怎样停止。名称听起来专业，不足以证明其中的方法适合当前任务。不同平台支持的安装和调用方式也可能不同，应按当前平台说明核对。

例如，一个Skill建议把所有异常值删除。你需要追问：它依据什么规则定义异常，是否区分录入错误与真实极端值，能否保留处理日志？若这些信息不清楚，就不应让它直接处理原始数据。

本课程的学习中，推荐利用Skill辅助检查格式、解释代码或组织记录，但是样本含义、统计前提、隐私授权和专业解释的判断是我们希望大家通过学习不断锻炼的能力，不建议不经过思考直接采用AI的建议或判断。

完成一次小检查：选一个当前可以查看说明的Skill，写出它解决的问题、允许操作和一项需要自己核验的风险。不要求为完成练习额外安装第三方资源。

## 2.5 课程项目目录、规则文件与输出约定

### 目录要能说明文件职责

可以从下面的最小结构开始；空目录中暂时没有文件也没有关系。

```text
my-course-project/
  README.md
  AGENTS.md
  data/
    raw/
    processed/
  scripts/
  outputs/
  records/
  references/
```

`data/raw/`保存原始输入，读取后不覆盖；`data/processed/`保存由规则和脚本生成的分析表。代码放在`scripts/`，图表和报告放在`outputs/`，运行与协作记录放在`records/`，数据字典、任务说明和允许使用的参考资料放在`references/`。

原始数据保护不等于永远不能纠正错误。若查证原始记录有误，应保存更正依据和新版本，并保留原文件，让别人能够看清变化发生在哪里。

`README.md`说明项目做什么、需要哪些文件和怎样开始。环境文件在需要时加入项目，并注明适用章节。不要把无关项目的配置复制进来，再让工具自行猜测使用顺序。

### 规则文件不等于权限设置

`AGENTS.md`可以记录稳定协作规则，例如：原始数据只读；不得猜补单位；结果写入指定目录；修改前保存快照；未经授权不上传数据。一次作业的具体问题则放进任务说明书。

规则文件是供协作工具和参与者阅读的说明，**不是操作系统层面的访问控制**。它不能替代文件权限、备份、平台授权或人工核验。是否支持读取该文件，以及怎样应用其中规则，也应在所用工具中确认。

文件名应能说明内容，例如`quality_flags.csv`和`environment-check.md`。不必给每个试验版本起复杂名称，但应能区分原始输入、正在编辑的文件和已经核验的产物。

## 2.6 环境验收、路径检查与常见排错

### 按依赖顺序检查

先确认工作空间，再看程序入口，然后检查包和输入，最后查看输出。这样能减少没有依据的重装。程序找不到文件时，第一步通常是核对路径，而不是升级全部依赖。

| 现象 | 首先核对 | 暂时不要做 |
| --- | --- | --- |
| 命令无法识别 | 软件是否安装、终端调用哪个入口 | 猜测并修改分析逻辑 |
| 缺少某个包 | 当前解释器和目标环境 | 在所有环境里重复安装 |
| 文件不存在 | 当前目录、相对路径、扩展名 | 新建一个同名空文件冒充输入 |
| Git报告非仓库 | 当前目录与仓库状态 | 以为Git未安装或历史已丢失 |
| 运行结束但无产物 | 实际输出路径、退出状态、日志 | 仅凭AI总结填写成功 |

回到章首的教学情境。假设项目名为my-course-project，输入保存在其中的data/raw/guesses.csv，代码使用的相对路径也是data/raw/guesses.csv。从项目根目录出发，它会找到预定文件；如果终端当前位于scripts目录，同样的写法就会去找scripts下面的data/raw/guesses.csv。编辑器里能看见原文件，不会改变这个寻找过程。因此，看到“文件不存在”后，先查当前目录和解析后的完整路径，两者对照起来，才能确定到底找错了哪里。

在PowerShell中，`Get-Location`显示当前目录，`Test-Path`检查指定路径是否存在。若当前目录不符合练习要求，就切换到要求的位置再试；若目录正确，则继续查文件名、扩展名和所在层级。不要一看到报错就把所有相对路径换成自己的桌面绝对路径：这可能让本机暂时运行，却把共享项目变成只能在自己电脑上使用的脚本。第五章还会比较工作目录与脚本位置，并说明配套程序如何确定输入位置。

另一个容易混淆的情形是“明明安装了包，运行时仍说缺包”。电脑上若有两套Python，安装操作可能使用第一套，脚本却由第二套启动。第二套不会因为第一套装过某个包就自动拥有它。此时先看2.3节检查命令输出的解释器位置，再与计划使用的环境核对；确认入口以后，才判断是否真的需要安装。路径问题查路径，环境问题查入口，这样每次修改都有对应的依据。

### 提交环境验收包

本章提交一份简短记录，包含项目路径、Python/R真实入口与输出、所需包状态、目录职责和一条具体核对说明。若发生失败，保留原始报错、已经尝试的操作和下一步；若全部通过，就说明如何确认调用了正确程序，不必人为制造错误。

还应注明哪些项目尚未测试。例如，现有电脑上的脚本能运行，不代表在另一台全新电脑上也完成了安装验证；CSV练习通过，也不代表Excel扩展已经配置。不同范围分别报告，才能准确判断是否可以继续。

### 知识结构

```mermaid
flowchart LR
A[工作空间与授权] --> B[程序入口]
B --> C[当前依赖]
C --> D[最小运行]
D --> E[真实输出与退出状态]
E --> F[验收记录]
G[项目目录与规则] --> A
G --> F
```

环境准备到能完成下一项学习任务即可。第三章将用这里已经确认的路径、范围和输出要求，写出可以执行和核验的AI任务说明书。
