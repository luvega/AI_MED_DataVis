## 本章定位

本章帮助学生把“想让 AI 帮忙”的模糊想法，整理成目标清楚、边界清楚、可以核验、可以留痕的任务说明书。它不是提示词技巧汇编，而是后续数据处理、代码生成、图表制作和报告写作前的协作规范训练。

本章承接第二章的数据分析流程与文件组织，也为第四章以后的 Python、R、可视化和项目报告打基础。学生完成本章后，应能说明自己让 AI 做了什么、依据什么核验结果、哪些内容仍需人工确认。

## 小节目录

### 3.1 从提示词到任务说明书

内容要点：

- 区分 Prompt 和 AI 任务说明书。Prompt 是一次具体指令，AI 任务说明书是结构化、可复用、可核验的任务描述。
- 用医药数据学习场景展示模糊指令的风险，例如目标不清、数据边界不清、输出格式不清、核验方式缺失。
- 引导学生把“帮我分析这个数据”改写为包含目标、上下文、约束、验证和输出的说明。
- 说明任务说明书的价值：减少误解，便于复查，也便于同伴或教师判断 AI 协作过程是否可靠。

### 3.2 目标、上下文、约束、验证与输出

内容要点：

- 目标：说明本次任务要完成什么，不把多个目标混在一句话里。
- 上下文：说明数据来源、字段含义、课程任务背景、已有处理步骤和学生已知条件。
- 约束：说明不能使用哪些材料、不能新增哪些结论、输出格式和命名要求是什么。
- 验证：说明如何检查 AI 输出，例如运行代码、核对列名、检查图表变量、比对原始数据、标注疑点。
- 输出：说明交付物类型、文件名、保存位置和读者对象。
- 使用统一模板训练学生写出一份可执行的 AI 任务说明书。

### 3.3 AI 辅助代码生成与人工核验

内容要点：

- 说明 AI 可以辅助生成代码、解释报错和提出修改建议，但不能替代学生理解代码。
- 学生至少要检查文件路径、列名、数据类型、筛选条件、统计口径和输出结果。
- 代码能运行不等于分析正确；图表能生成不等于解释成立。
- 涉及医药、临床、组学或药物信息时，应区分数据观察、方法输出、允许解释和仍需验证内容。
- 对无法确认的结果使用 `需补证据` 或 `需人工确认` 标注。

### 3.4 AI 协作记录与版本留痕

内容要点：

- AI 协作记录至少包含：任务、原始 Prompt、AI 输出摘要、人工核验、人工修改、最终结果和反思。
- 版本留痕包括文件命名、修改前后对照、结果文件夹和必要的 Git 记录。
- 简要说明 Git 的作用：记录修改、查看差异、回退错误和支持协作交接。
- 本节重点不是讲 Git 命令大全，而是训练学生保留可追踪证据。
- 协作记录应服务课程评价，体现学生有没有独立判断，而不是只展示 AI 生成内容。

### 3.5 学术诚信、数据伦理与隐私保护

内容要点：

- AI 生成文本、代码和图表都需要人工核验，不能伪造数据、文献、统计结果或实验结论。
- 使用 AI 时应说明协作范围，避免把 AI 输出包装成未经核验的个人结论。
- 涉及患者、临床或敏感信息时，应遵守去标识化和课程数据使用要求。
- 不根据课堂练习数据直接提出临床建议、药物疗效判断或机制结论。
- 证据不足处标注 `需补证据` 或 `需人工确认`，把已知内容和推断内容分开。

## 主张、证据与边界

| 主张 | 证据来源 | 写作边界 |
| --- | --- | --- |
| 结构化任务说明书能降低沟通偏差 | 五栏任务说明书、统一模板和提示词样例 | 不写成保证 AI 一定正确 |
| AI 代码生成后必须人工核验 | 课程大纲、生成式 AI 数据分析资料、提示词样例 | 不把“代码能运行”写成“分析正确” |
| AI 协作记录是课程学习证据 | 课程大纲成绩评定和协作记录模板 | 不要求学生记录所有闲聊，只保留关键版本 |
| Git 和文件命名能支持版本留痕 | Git 章节材料和项目输出约定 | 不展开成完整 Git 教程 |
| 医药数据解释必须保留伦理和证据边界 | 课程思政要求、术语表、生成式 AI 隐私段落 | 不新增临床建议、因果解释或机制结论 |

## 需补证据与需人工确认

| 位置 | 缺口 | 处理方式 |
| --- | --- | --- |
| 医药案例数据 | 本章暂无指定真实数据集 | 正文使用教学模拟场景，不写真实样本量 |
| AI 平台差异 | 不同模型能力、接口和隐私政策会变化 | 正文写原则，不写具体平台结论 |
| Git 使用深度 | 本章只讲留痕，不承担完整版本控制教学 | 具体命令留给第2章和附录B衔接 |
| 伦理规范细则 | 未提供学校或机构正式 AI 使用政策文本 | 正文标注课程边界和 `需人工确认` |

## 本章正文写作要求

- 采用自然、克制的中文表达，避免翻译腔和空泛铺垫。
- 每个技术术语首次出现时给出简明解释，后文保持同一译名。
- 按“是什么、为什么、怎么检查”展开，不用形象类比解释技术概念。
- 涉及医药数据解释时，按“观察结果、方法来源、允许解释、替代解释、仍需验证”控制边界。
- 正文需包含知识结构图或知识图谱生成提示词，并用 Mermaid、表格或清单提供准确结构。
